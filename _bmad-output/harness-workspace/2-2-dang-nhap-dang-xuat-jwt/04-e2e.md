## Note fix HIGH-1 / MEDIUM-1 — verify trạng thái sau fix

### HIGH-1 — Logout unverified `jwt.decode` → DoS (FIXED, verified)
- **Trước fix:** POST /auth/logout không guard, service dùng `jwt.decode` (không verify signature) extract sub → `admin.signOut(sub,'global')`. Attacker sửa sub → forced-logout DoS.
- **Sau fix (verify thật):**
  - `auth.controller.ts:76` thêm `@UseGuards(JwtAuthGuard)` cho logout → guard verify JWT signature trước khi vào controller.
  - `auth.service.ts:311` `logout(userId: string)` — nhận userId đã verify từ `req.user.id` (guard attach), KHÔNG còn `jwt.decode`.
  - Test 12: logout valid JWT → 200 + clear cookie ✅
  - Test 13: logout no-token → 401 "Thiếu token xác thực" (guard reject) ✅ — E6 behavior thay đổi đúng (không token = không session để logout)
  - Test 14: logout modified JWT (sub changed, no re-sign) → 401 "Token hết hạn hoặc không hợp lệ" (signature invalid, guard reject) ✅
- **Kết luận HIGH-1:** FIXED + verified thật. DoS vector đóng.

### MEDIUM-1 — JwtAuthGuard không validate iss (FIXED, verified)
- **Trước fix:** guard verify signature + exp nhưng KHÔNG check `payload.iss === ${SUPABASE_URL}/auth/v1`.
- **Sau fix (verify thật):**
  - `jwt-auth.guard.ts:60-65`: sau `jwt.verify` (HS256 path), `expectedIss = ${SUPABASE_URL}/auth/v1`, `payload.iss !== expectedIss → throw UnauthorizedException`. iss mismatch → reject immediately (KHÔNG fallback ES256).
  - Test 16a: HS256 JWT correct iss → 200 ✅
  - Test 16b: HS256 JWT wrong iss (`http://evil-supabase.example.com/auth/v1`) → 401 ✅
  - ES256 fallback (`supabase.auth.getUser`) validate iss server-side → không cần check thêm.
- **Kết luận MEDIUM-1:** FIXED + verified thật. Defense-in-depth đóng.

## Note nuance

### Hybrid JWT guard (HS256 local + ES256 fallback)
- `jwt-auth.guard.ts` hybrid: (1) `jwt.verify(token, SUPABASE_JWT_SECRET)` HS256 local fast-path (~0.1ms, no network); (2) fallback `supabase.auth.getUser(token)` cho ES256 (new Supabase v2.188+ asymmetric keys).
- Local Supabase v2.188.1 issue JWT ES256 (alg=ES256, kid=b81269f1-...) → HS256 path fail signature → ES256 fallback work. Test 8/12 dùng ES256 token thật → 200.
- HS256 path verify riêng bằng manually-signed JWT (test 16a/16b) — correct iss → 200, wrong iss → 401.
- **KHÔNG phải bug** — design hybrid đúng cho cả old (HS256) + new (ES256) Supabase.

### ThrottlerModule in-memory (MEDIUM-2 defer)
- `auth.module.ts:27` `ThrottlerModule.forRoot` mặc định in-memory storage. Rate limit 5/15min/IP đếm per-instance. Single-container deploy (Story 1.3) → OK. Multi-instance → 5×N (MEDIUM-2 latent).
- **Defer** — cần story riêng dùng `throttler-storage-redis` với REDIS_URL đã có. KHÔNG block AC9/E9 (single-instance verify pass).

### PII redact residual (LOW, non-blocking)
- pino redact paths (`logger.module.ts:27`): `req.headers.authorization`, `req.headers.cookie`, `*.password`, `*.token`, `*.accessToken`, `*.refreshToken`, `*.email`, `*.phone`, ... — auth business log sạch (action/reason/userId, 0 raw email/password/JWT).
- **Residual:** `res.headers['set-cookie']` KHÔNG nằm trong redact paths → pino HTTP auto-logger log raw `set-cookie: refresh_token=<value>; ...` trong request-completed log (1 occurrence). refresh_token value leak vào response header log.
- **Severity:** LOW — refresh_token không phải PII (session token, rotate + revoke qua logout), nhưng AD-8 intent "refresh_token KHÔNG log raw" bị partial undermine. Recommend thêm `res.headers['set-cookie']` vào redact paths (follow-up). KHÔNG block AC9 (auth service không log token raw, chỉ HTTP auto-logger response header).
