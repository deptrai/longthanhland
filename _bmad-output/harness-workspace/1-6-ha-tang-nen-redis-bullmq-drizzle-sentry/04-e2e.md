## Note M1 từ review (QueueModule shutdown order)

- **Finding M1 (MEDIUM, non-blocking):** `QueueModule.onModuleDestroy()` gọi `this.redis.quit()` TRƯỚC khi BullMQ Worker (EchoProcessor) đóng → unhandled "Connection is closed" event lúc shutdown. Reproduced trong e2e teardown (Jest bắt được, exit 0).
- **Verify trạng thái:** Code `queue.module.ts:54-60` vẫn còn `await this.redis.quit()` trong `onModuleDestroy`. KHÔNG fix trong story này (review đánh dấu non-blocking, recommendation fix trước deploy prod).
- **Đánh dấu:** Fix sau (patch riêng hoặc story tiếp theo). KHÔNG ảnh hưởng AC, KHÔNG ảnh hưởng runtime khi app đang chạy — chỉ ảnh hưởng teardown hygiene. Production với `app.enableShutdownHooks()` + SIGTERM có thể exit code ≠ 0 → cần fix trước khi Dokploy/K8s deploy.
- **Các LOW (L1-L4):** Non-blocking, không verify thêm (package.json duplicate, err.message sanitize, pino unit test, Sentry over-redaction) — để story sau.
